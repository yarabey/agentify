# agent — демон на машине пользователя

## Назначение и бизнес-контекст

Агент — Go-демон, который пользователь ставит на свою машину **одной командой**
(FR C1, C5). В отличие от оркестратора и бота, агент **не входит в наш
`docker compose`** — он собирается в CI (GoReleaser) и распространяется как
бинарь + `install.sh` на машины пользователей
([`docs/01_tech_stack_and_architecture.md` §1, РЕШЕНИЕ 1/2](../docs/01_tech_stack_and_architecture.md)).

Роль агента в системе:

- держит **исходящий WebSocket** к оркестратору (auth по UUID, авто-реконнект),
  чтобы не открывать входящих портов и работать за NAT (РЕШЕНИЕ 1, EPIC 3.3);
- хранит локальный **durable outbox** (bbolt), переживающий падение оркестратора
  и рестарт агента, — гарантия «ничего не теряется» (FR E3, EPIC 3.5);
- запускает провайдеров **Claude API** и **Claude Code CLI** как подпроцессы,
  перехватывая согласование команд по allowlist (FR C3, EPIC 4.5).

## Что реализовано сейчас (тикеты 0.6, 3.3)

**Общий операционный каркас** из пакета [`internal/platform`](../internal/platform):
загрузка конфига из env, slog, эндпоинт `GET /healthz`, graceful shutdown по
SIGTERM/SIGINT (тикет 0.6).

`/healthz` и graceful shutdown нужны агенту уже сейчас: под управлением
**systemd/launchd** (FR C5) демон должен корректно останавливаться по сигналу и
давать менеджеру служб точку проверки живости.

**WS-транспорт к оркестратору** из пакета
[`agent/internal/wsclient`](internal/wsclient) (тикет 3.3, `docs/protocol.md`
§1, §2, §4): исходящее WS-соединение к `/machine/ws`, аутентификация первым
кадром `hello` (UUID интеграции, FR B3), авто-реконнект с экспоненциальным
backoff (full jitter) при любом разрыве — бесконечно, пока агент не получит
сигнал остановки. Запускается конкурентно с `/healthz` на общем
сигнал-чувствительном контексте (`errgroup`). Опционален: при пустом
`AGENT_ORCHESTRATOR_WS_URL` агент работает как в тикете 0.6 (только
`/healthz`), без WS вовсе.

Полноценная обработка команд/событий (task_assigned, agent_question, ack и
т.д.), ACK/offset-семантика, Redpanda-мост и локальный durable outbox
(bbolt) — будущие тикеты (3.4, 3.5, 5.x).

## Конфигурация (env)

Все переменные — с префиксом `AGENT_`. Дефолты рассчитаны на запуск в dev без
единой переменной.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `AGENT_ENV` | `dev` | Режим выполнения: `dev` или `prod`. Влияет на формат логов по умолчанию. |
| `AGENT_LOG_LEVEL` | `info` | Уровень логирования: `debug`/`info`/`warn`/`error`. |
| `AGENT_LOG_FORMAT` | по `ENV` (`json` в prod, `text` в dev) | Формат slog: `json` или `text`. |
| `AGENT_HEALTH_ADDR` | `:8080` | Адрес HTTP-сервера с `/healthz`. |
| `AGENT_SHUTDOWN_TIMEOUT` | `10s` | Крайний срок graceful-остановки HTTP-сервера. |
| `AGENT_ORCHESTRATOR_WS_URL` | пустая строка (WS отключён) | WS-адрес `/machine/ws` оркестратора (`ws://...`/`wss://...`). Пусто — агент работает только с `/healthz`, как в тикете 0.6, без WS-транспорта вовсе. |
| `AGENT_INTEGRATION_UUID` | пустая строка | UUID интеграции (секрет, выданный при создании интеграции, `POST /integrations`, тикет 2.2; FR B2/B3). Обязателен, если задан `AGENT_ORCHESTRATOR_WS_URL` — иначе фатальная ошибка старта. |
| `AGENT_PROVIDERS` | пустая строка (пустой список) | Список провайдеров агента через запятую (например `claude,claude-code`, EPIC 4.5), передаётся в hello-кадре. |

Выбор провайдера и его креды — хранятся локально, в оркестратор не уходят
(FR C4/J1) — добавляются под тем же префиксом `AGENT_` в EPIC 4.

## Запуск локально

```bash
go run ./agent                    # dev: text-лог, /healthz на :8080
AGENT_ENV=prod go run ./agent     # prod: JSON-лог
curl -s localhost:8080/healthz    # {"status":"ok","service":"agent"}
```

Остановка — `Ctrl+C` (SIGINT) или `kill -TERM <pid>`: демон гасится gracefully.
