# User stories и критерии приёмки (Gherkin)

> Сценарии покрывают объём MVP. Ключевые слова — на русском (Cucumber/Behave это поддерживают).
> Каждая `Функция` = пользовательская ценность; `Сценарии` внутри = критерии приёмки.

---

## 1. Регистрация и доступ

```gherkin
# language: ru
Функция: Доступ по токену регистрации
  Как владелец закрытой системы
  Я хочу впускать только тех, у кого есть секретный токен
  Чтобы система оставалась приватной

  Сценарий: Успешная регистрация по валидному токену
    Дано у меня есть валидный токен регистрации
    Когда я регистрируюсь, указав этот токен и учётные данные
    Тогда аккаунт создаётся
    И я могу войти в систему

  Сценарий: Регистрация без токена запрещена
    Дано у меня нет токена регистрации
    Когда я пытаюсь зарегистрироваться
    Тогда система отклоняет регистрацию

  Сценарий: Администратор видит токен регистрации
    Дано я вошёл как администратор
    Когда я открываю настройки в веб-интерфейсе
    Тогда я вижу действующий секретный токен регистрации

  Сценарий: Изоляция данных между пользователями
    Дано существуют пользователи "Аня" и "Борис" со своими задачами
    Когда "Аня" просматривает свои задачи и интеграции
    Тогда она видит только свои данные
    И не видит ничего, принадлежащего "Борису"

  Сценарий: Доступ к API по токену
    Дано я вошёл и получил токен доступа
    Когда я вызываю метод API с этим токеном
    Тогда система определяет меня как владельца токена
    И выполняет операцию от моего имени
```

## 2. Интеграции и машины

```gherkin
# language: ru
Функция: Управление интеграциями
  Как пользователь
  Я хочу описывать свои машины как интеграции
  Чтобы направлять в них задачи

  Сценарий: Создание интеграции выдаёт UUID
    Дано я вошёл в систему
    Когда я создаю интеграцию с названием "Домашний сервер"
    Тогда система выдаёт уникальный UUID для этой интеграции
    И UUID доступен мне для настройки машины

  Сценарий: Аутентификация машины по UUID
    Дано у интеграции есть UUID
    Когда машина обращается к системе с этим UUID
    Тогда система принимает её как данную интеграцию

  Сценарий: IP — необязательная проверка
    Дано у интеграции не указан IP
    Когда машина с динамическим адресом обращается с валидным UUID
    Тогда система её принимает

  Сценарий: Редактирование интеграции не рвёт активные задачи
    Дано в интеграции есть выполняющаяся задача
    Когда я меняю её название
    Тогда выполняющаяся задача продолжается без сбоя

  Сценарий: Удаление интеграции с активной задачей требует подтверждения
    Дано в интеграции есть выполняющаяся задача
    Когда я пытаюсь удалить интеграцию
    Тогда система просит подтверждения
    И корректно завершает или отменяет активную задачу
```

```gherkin
# language: ru
Функция: Статус машины
  Как пользователь
  Я хочу видеть, на связи ли машина
  Чтобы понимать, дойдёт ли задача

  Сценарий: Машина онлайн
    Дано машина подключена и шлёт сигналы о себе через очередь
    Когда я открываю список интеграций
    Тогда машина отображается как "онлайн"

  Сценарий: Машина оффлайн
    Дано машина не выходила на связь дольше порога
    Когда я открываю список интеграций
    Тогда машина отображается как "оффлайн"
    И статус обновился асинхронно, без живого соединения
```

## 3. Подключение машины разработки

```gherkin
# language: ru
Функция: Установка агента одной командой
  Как пользователь
  Я хочу развернуть агента на машине одной командой
  Чтобы быстро подключить новую машину

  Сценарий: Установка на чистой системе
    Дано чистая macOS или Ubuntu
    Когда я выполняю однострочную команду установки
    Тогда скрипт ставит всё необходимое
    И интерактивно спрашивает адрес оркестратора, UUID и провайдера
    И после настройки агент работает в фоне

  Сценарий: Пользователь выбирает провайдера сам
    Дано идёт интерактивная настройка
    Когда меня спрашивают про провайдера ИИ
    Тогда я выбираю Claude или Claude Code и указываю свои учётные данные провайдера
    И система не управляет оплатой провайдера
```

## 4. Постановка задачи

```gherkin
# language: ru
Функция: Постановка задачи через любой канал
  Как пользователь
  Я хочу ставить задачи из web и из Telegram
  Чтобы работать из удобного места

  Структура сценария: Постановка задачи из канала
    Дано я авторизован в канале "<канал>"
    И у меня есть подключённая интеграция
    Когда я создаю задачу с текстом "Добавь аутентификацию" для этой интеграции
    Тогда задача попадает в очередь к нужной машине
    И появляется в моей истории со статусом "в очереди"

    Примеры:
      | канал    |
      | web      |
      | telegram |

  Сценарий: Защита от двойной отправки
    Дано я только что отправил задачу
    Когда я случайно отправляю ту же задачу повторно
    Тогда дубликат задачи не создаётся
```

## 5. Вопрос-ответ и согласование команд

```gherkin
# language: ru
Функция: Диалог пользователя с агентом
  Как пользователь
  Я хочу отвечать агенту на вопросы и согласовывать команды
  Чтобы управлять ходом работы асинхронно

  Сценарий: Агент задаёт вопрос и получает ответ
    Дано агент выполняет мою задачу
    Когда агенту нужно решение и он задаёт вопрос
    Тогда задача переходит в статус "ожидает ответа пользователя"
    И я получаю уведомление
    Когда я отвечаю на вопрос
    Тогда агент продолжает работу

  Сценарий: Команда из allowlist выполняется без вопроса
    Дано команда входит в allowlist (как в Claude Code)
    Когда агент хочет её выполнить
    Тогда она выполняется без запроса согласования

  Сценарий: Команда вне allowlist требует согласования
    Дано команда не входит в allowlist
    Когда агент хочет её выполнить
    Тогда задача переходит в "ожидает ответа пользователя"
    И я получаю запрос на согласование
    Но команда не выполняется, пока я её не одобрю

  Сценарий: Отклонение команды
    Дано агент запросил согласование команды вне allowlist
    Когда я отклоняю команду
    Тогда команда не выполняется
    И агент действует с учётом отказа

  Сценарий: Несколько вопросов сопоставляются корректно
    Дано агент задал два вопроса
    Когда я отвечаю на второй вопрос
    Тогда ответ привязывается именно ко второму вопросу
```

## 6. Уведомления

```gherkin
# language: ru
Функция: Уведомления о точках решения
  Как пользователь
  Я хочу получать уведомление, когда от меня ждут ответа
  Чтобы не пропустить и не потерять задачу

  Сценарий: Уведомление в web по WebSocket
    Дано у меня открыт веб-интерфейс
    Когда агент задаёт вопрос по моей задаче
    Тогда я вижу уведомление в web без перезагрузки страницы

  Сценарий: Уведомление в Telegram
    Дано мой Telegram привязан к аккаунту
    Когда агент задаёт вопрос по моей задаче
    Тогда мне приходит сообщение в Telegram
```

## 7. Завершение задачи

```gherkin
# language: ru
Функция: Явное подтверждение завершения
  Как пользователь
  Я хочу сам решать, когда задача закрыта
  Чтобы система не закрывала её за меня

  Сценарий: Агент сообщил о завершении — задача ещё не закрыта
    Дано агент выполнил работу
    Когда агент сообщает о завершении
    Тогда задача переходит в статус "ожидает подтверждения"
    Но не считается завершённой

  Сценарий: Пользователь подтверждает завершение
    Дано задача в статусе "ожидает подтверждения"
    Когда я явно подтверждаю завершение
    Тогда задача переходит в статус "завершена"

  Сценарий: Пользователь отклоняет результат
    Дано задача в статусе "ожидает подтверждения"
    Когда я отклоняю результат и прошу доработку
    Тогда задача возвращается в статус "выполняется"
```

## 8. Отмена задачи

```gherkin
# language: ru
Функция: Безопасная отмена
  Как пользователь
  Я хочу остановить задачу
  Чтобы прекратить ненужную или ошибочную работу

  Сценарий: Отмена доходит до машины
    Дано задача выполняется на машине
    Когда я отменяю задачу
    Тогда команда отмены доходит до машины
    И агент останавливается
    И статус во всех каналах становится "отменена"

  Сценарий: Приоритет сохранности данных при отмене
    Дано агент в середине критической операции
    Когда я отменяю задачу
    Тогда система доводит критическую операцию до безопасного состояния
    И предупреждает меня, что мгновенная остановка не гарантируется
```

## 9. Асинхронность и оффлайн

```gherkin
# language: ru
Функция: Устойчивость к оффлайну
  Как пользователь
  Я хочу, чтобы работа не терялась при потере связи
  Чтобы доверять системе длительные задачи

  Сценарий: Задача поставлена при оффлайн-машине
    Дано машина сейчас оффлайн
    Когда я ставлю задачу в эту интеграцию
    Тогда задача ждёт в очереди
    Когда машина снова выходит онлайн
    Тогда она получает задачу и начинает выполнение

  Сценарий: Оркестратор временно недоступен
    Дано машина выполнила часть работы
    И оркестратор временно недоступен
    Когда связь восстанавливается
    Тогда накопленные сообщения от машины обрабатываются
    И ничего не теряется

  Сценарий: Машина пропала надолго
    Дано задача выполнялась
    Когда машина не выходит на связь дольше порога
    Тогда задача помечается как "зависла"
    И я получаю уведомление
    Когда машина возвращается
    Тогда выполнение может быть продолжено
```

## 10. История

```gherkin
# language: ru
Функция: История задач и ответов
  Как пользователь
  Я хочу видеть и контролировать историю
  Чтобы проверять результаты и управлять задачами

  Сценарий: Состав записи о задаче
    Дано задача прошла полный цикл
    Когда я открываю её в истории
    Тогда я вижу целевую интеграцию, таймстемп, текст запроса, статус и текстовый ответ
    И вижу свои ответы с таймстемпами, привязанные к запросу

  Сценарий: Бессрочное хранение
    Дано задача завершена давно
    Когда я открываю историю
    Тогда старая задача по-прежнему доступна
    И авто-удаления не происходит

  Сценарий: Действия из истории в web
    Дано в истории есть активная задача
    Когда я открываю её в веб-интерфейсе
    Тогда я могу её отменить, ответить на вопрос или подтвердить завершение
```
