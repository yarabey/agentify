# Глоссарий проекта

Единый словарь терминов оркестратора. Источник — §4 бизнес-ТЗ
([`ТЗ_Оркестратор_бизнес-версия.md`](./ТЗ_Оркестратор_бизнес-версия.md)) и
[`01_tech_stack_and_architecture.md`](./01_tech_stack_and_architecture.md).
Назначение — чтобы код, доки и общение использовали одни и те же слова в одном
значении (AGENTS.md §2: глоссарий поддерживается при появлении новых терминов).

> Договорённость: новый сквозной термин сначала появляется здесь, потом — в коде.

## Роли и компоненты

- **Оркестратор** — центральный сервис: аутентификация, хранение, маршрутизация
  сообщений, история задач, конечный автомат (FSM) задачи. Точка, через которую
  ходят все каналы и все машины. Реализация — Go (REST + WebSocket).
- **Агент** — Go-демон на машине пользователя: принимает задачи от оркестратора,
  запускает провайдера (Claude / Claude Code), шлёт прогресс и вопросы обратно.
  Работает за NAT (нет входящих портов), переживает обрывы связи за счёт outbox.
- **Провайдер** — конкретный исполнитель внутри агента: Claude API или Claude Code
  CLI. Провайдера и подписку настраивает сам пользователь при установке агента.
- **Канал** — источник пользовательского ввода и уведомлений: web-PWA или
  Telegram-бот. Все каналы работают через единый API оркестратора.

## Интеграции и машины

- **Машина разработки (интеграция)** — машина пользователя с запущенным агентом,
  подключённая к оркестратору. В системе описывается сущностью «интеграция».
- **Интеграция** — запись об одной машине: обязательное название и опциональный
  IP-«хинт». При создании система выдаёт ей UUID.
- **UUID интеграции** — уникальный идентификатор интеграции, выдаётся системой и
  трактуется как **секрет**: на нём строится аутентификация машины (FR B2/B3).
  Ротация/отзыв UUID — post-MVP.
- **IP-хинт** — необязательная дополнительная проверка адреса машины; отключаема
  для машин с динамическим IP.

## Задачи и взаимодействие

- **Задача (запрос)** — сформулированная пользователем работа для агента; основная
  единица жизненного цикла, проходит через FSM.
- **Вопрос агента** — запрос решения/разрешения от агента к пользователю в ходе
  выполнения задачи (цикл «вопрос — ответ»).
- **Согласование действия** — частный случай вопроса агента: разрешить ли выполнить
  конкретную команду.
- **Allowlist** — список заранее разрешённых команд (по принципу Claude Code):
  команда из списка выполняется без переспрашивания, прочие требуют согласования.

## Состояния задачи (FSM)

- **FSM (конечный автомат задачи)** — явная модель состояний задачи с переходами,
  отменой и базовыми таймаутами. Ключевой инвариант: **завершённой задачу делает
  только явное действие пользователя**, а не отчёт агента.
- **«Агент сообщил о завершении»** — отдельный промежуточный статус: агент отчитался,
  но задача ещё не закрыта; закрытие — за пользователем (FR E2, Gherkin §7).
- **Отмена** — пользовательский переход, прекращающий выполнение задачи.

## Надёжность и доставка сообщений

- **Шина сообщений** — асинхронный канал между машиной и оркестратором (Redpanda).
  Все взаимодействия машина ↔ оркестратор асинхронны: оффлайн-сторона догоняет
  работу, когда снова онлайн.
- **Outbox** — локальное durable-хранилище на стороне агента (bbolt/BoltDB):
  переживает перезапуск агента и недоступность оркестратора, реплеит накопленные
  сообщения при реконнекте (Gherkin §9).
- **Heartbeat** — периодический сигнал «я жив» от агента через шину; по его
  отсутствию дольше таймаута оркестратор переводит интеграцию в `offline` (FR B4).
- **Статус машины (онлайн/оффлайн)** — индикатор активности интеграции в UI,
  вычисляемый асинхронно из heartbeat, без живого синхронного соединения.

## Доступ и аккаунты

- **Токен регистрации** — секретный токен, без которого регистрация невозможна
  (закрытый доступ, FR A1). Виден администратору в веб-интерфейсе; ротация/отзыв —
  post-MVP.
- **Токен доступа** — выдаётся при логине (access-JWT, короткий TTL); поддерживаются
  обновление (refresh) и выход (отзыв) — FR A3.
- **Изоляция данных** — гарантия, что каждый пользователь видит и редактирует только
  свои задачи и интеграции (FR A4); на уровне БД подкрепляется Postgres RLS.
