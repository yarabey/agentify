# Roadmap по фазам

> Планирование поставки на основе бизнес-ТЗ. Каждая фаза — самостоятельная ценность, которую можно использовать, не дожидаясь следующей.

---

## Обзор

| Фаза | Тема | Главная цель | Готовность = |
|---|---|---|---|
| **MVP** | «Работает для меня» | Поставить задачу агенту на своей машине из web/Telegram и довести до результата | Сквозной сценарий проходит на одном пользователе и одной-двух машинах |
| **Фаза 2** | «Надёжно и под контролем» | Масштаб, безопасность действий, видимость, удобство | Можно доверить системе длительные и рискованные задачи без надзора у терминала |
| **Фаза 3+** | «Для других людей» | Открыть платформу за пределы себя | Новый пользователь онбордится сам, безопасно и без участия владельца |

---

## MVP — «Работает для меня»

**Цель:** доказать ядро ценности — асинхронное управление агентом на своей машине из любого канала.

**Что входит:**
- Доступ: регистрация по токену (токен виден администратору в web), логин, обновление токена, выход.
- Интеграции: создание/редактирование/удаление, выдача UUID, аутентификация машины по UUID.
- Машина: установка одной командой (macOS/Ubuntu), фоновый агент, провайдеры Claude и Claude Code; провайдер настраивает пользователь.
- Каналы: web-PWA (полный) + Telegram (ввод и уведомления), единый API.
- Задачи: постановка, конечный автомат статусов, цикл «вопрос-ответ», согласование команд по allowlist (как в Claude Code).
- Завершение: только явным действием пользователя; «агент сообщил о завершении» — отдельный статус.
- Уведомления: в web по WebSocket, в Telegram.
- Асинхронность: всё машина ↔ оркестратор через очередь; оффлайн-сторона догоняет.
- Статус машины (онлайн/оффлайн) асинхронно.
- История с изоляцией по пользователю, хранение бессрочно.

**Рекомендуемый порядок сборки внутри MVP:**
1. Каркас доступа (регистрация/логин/токены) + изоляция пользователя.
2. Интеграции и выдача UUID.
3. Канал очереди машина ↔ оркестратор (фундамент всего) + статус машины.
4. Установочный скрипт + фоновый агент с одним провайдером (Claude Code).
5. Постановка задачи и конечный автомат статусов.
6. Цикл «вопрос-ответ» + согласование команд (allowlist).
7. Уведомления (WebSocket, затем Telegram).
8. История, отмена, явное подтверждение завершения.
9. Web-PWA как полноценный канал, второй провайдер (Claude).

**Критерий выхода из MVP:** один пользователь ставит задачу из web и из Telegram, агент задаёт вопрос → приходит уведомление → пользователь отвечает → агент завершает → пользователь подтверждает. Оффлайн-машина догоняет задачу после подключения. Отмена останавливает агента безопасно.

## Фаза 2 — «Надёжно и под контролем»

**Цель:** сделать систему такой, чтобы ей можно было доверять длительные и рискованные задачи без присмотра.

**Что входит:**
- Масштаб: несколько агентов на машине, дополнительные провайдеры/агенты, квоты на параллельность как защита от перегруза.
- Безопасность действий: расширенные политики разрешений поверх allowlist, песочница агента.
- Видимость: аудит-журнал, прогресс долгих задач.
- Удобство: мягкие напоминания о задачах, ожидающих подтверждения; web push-уведомления (когда вкладка закрыта); маршрутизация уведомлений между несколькими активными каналами; email-фолбэк.
- Доступ: ротация/отзыв токена регистрации и UUID.

**Критерий выхода:** пользователь запускает рискованную многошаговую задачу, уходит, получает уведомления о точках решения, видит прогресс и аудит, безопасно управляет разрешениями. Забытая на подтверждении задача напоминает о себе.

## Фаза 3+ — «Для других людей»

**Цель:** открыть платформу за пределы владельца (если продукт окажется удобным).

**Что входит:**
- Командная работа: роли, общий доступ к интеграциям.
- Самостоятельный онбординг новых пользователей.
- Восстановление пароля, MFA, корпоративные политики.
- Новые каналы: другие мессенджеры, IDE-плагины, CLI.
- Возможное публичное открытие платформы.

**Критерий выхода:** новый пользователь регистрируется и доходит до первой выполненной задачи самостоятельно, без участия владельца, с приемлемым уровнем безопасности.

---

## Принципы приоритизации

- **Сначала фундамент очереди** — на нём держится вся асинхронность; без него остальное не имеет смысла.
- **Безопасность действий растёт с автономностью** — чем меньше пользователь смотрит за агентом, тем строже нужны разрешения и аудит (поэтому это Фаза 2, а не позже).
- **Открытие для других — последним** — мультитенант-изоляция в MVP уже есть, но полноценная безопасность чужих пользователей дороже и не нужна, пока система «для себя».
